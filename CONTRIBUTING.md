# Contributing

Thanks for helping out. The short version:

1. Create a branch from `main` named `<type>/<short-description>` (see `docs/branching-strategy.md`).
2. Keep each pull request focused on one change.
3. Write commit messages following `docs/commit-conventions.md`.
4. Open a pull request using the template and link the issue it resolves.
5. Wait for CI and at least one review before merging.

## Local checks

Run the project's tests and linters before pushing. Do not commit secrets, `.env` files or build output.
